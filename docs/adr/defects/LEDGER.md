# Defect ledger

Newest first. One row per defect. See `README.md` for why the "should have caught it" column is the
one that matters, and `SHAPES.md` for the derived catalogue that feeds review briefs.

**Severity**: `S0` = destroys data and reports success (CLAUDE.md rule 6). `S1` = wrong result a user
would act on. `S2` = misleading output, no data loss. `S3` = internal/doc inaccuracy.

**Confidence**: `measured` = reproduced during this project's own work, numbers taken from a run.
`reconstructed` = backfilled from doc comments and ADRs after the fact; the shape is reliable, the
incidental detail is not.

## Reading this table

The `reconstructed` rows are deliberately thin. They are here because the *shapes* they contribute
are load-bearing — S-09, S-10 and S-11 all come from them, and S-10 has now produced three separate
severity zeros across the project's history. That recurrence is the argument for ADR 028 existing at
all, and it is only visible because the rows sit next to each other.
